# Phase II staged roadmap

**Status: proposed sequence.** Each stage is a gate; do not start the next stage until its exit evidence is reviewed and recorded. Protocol review is not permission to collect data.

| Stage | Work | Entry criteria | Exit criteria |
|---|---|---|---|
| **P2.0 — Protocol and calibration-plan approval** | Authors/supervisor provisionally approve the research questions, tracks, alternatives, limited calibration plan, personnel, and preliminary resources. | Independent review findings are addressed in the proposal; human approvals and governance requirements remain pending. | Required ethics, consent, source-access, privacy, and retention approvals are recorded; authorized calibration personnel and a limited plan are approved. The final A/B size remains undecided until calibration evidence and workload are reviewed. |
| **P2.0a — Authorized calibration and final size decision** | After all required human-subject, consent, source-access, privacy, and retention approvals, conduct only the approved 24-case nonbenchmark calibration; do not use M8 or eventual benchmark cases. | P2.0 calibration plan, personnel, and preliminary resource envelope approved; required governance approvals obtained; assessors and independent adjudicator appointed. | Calibration thresholds met or one versioned retraining/recalibration round completed; otherwise stop for supervisor decision. Review observed timing and disagreement, then obtain explicit author/supervisor approval and budget commitment for Option A or B before benchmark construction. |
| **P2.1 — Task/candidate curation** | Curate 36 task briefs and the approved 24- or 36-candidate pools from frozen public source frames. | P2.0/P2.0a complete; source access/reuse terms checked; deterministic group allocator and source registry versioned. | Source frames and snapshots, task-family groups, exact group-level split, candidate pools, source strata, provenance, exclusions, and family overlap are frozen and hashed; at least half of each pool is ranking-blind; no M8 task or exact M8 candidate snapshot is reused. Any infeasible quotas stop curation for redesign. |
| **P2.1a — Baseline-fidelity and metric-fixture gate** | Implement the minimal Phase II score/export adapters; verify native R1/R2/R3 behavior and metric edge cases using synthetic labels only. | P2.1 manifests are frozen but unannotated; score-only Track B contract and candidate-ID map are approved. | Native score formulas and R3 top-three/short outputs reproduce Phase I on identical inputs; track isolation, estimate preservation, tie/family/exhaustion behavior, score provenance, and all synthetic N/A/eligibility/assessability/slot fixtures pass. Any failure blocks P2.2. |
| **P2.2 — Independent annotation** | Annotate every frozen pair blind with two assessors; adjudicate all registered disagreements; preserve first-pass records. | P2.1/P2.1a complete; calibration and assessor workload approved; test custodian, secure storage, and access logging operational. | Required first-pass judgments and constraint states are complete or objectively excluded; adjudications are linked but do not overwrite originals; reliability, disagreement, N/A, and assessability summaries are reported; test relevance and eligibility remain sealed. If the 25% task-batch or split pause threshold is exceeded, pause and follow the versioned review/reannotation rule. |
| **P2.3 — Analysis and model-pipeline lock** | Use approved train/development data to finalize features, score-only Track B rankings, model fitting, metrics, exclusions, and resource logging without opening test labels. | P2.2 complete; only train/development labels released to authorized analysts; held-out labels remain with custodian. | Code, feature provenance, model/configuration, baseline outputs, metric denominators, exclusions, and analysis hashes reviewed and locked. Any test-label or test-outcome access blocks confirmatory status. |
| **P2.4 — Train/development model selection** | Fit the single pairwise linear ranker; select regularization on development tasks; run the registered evidence-feature ablation. | P2.3 frozen; authorized train/development labels available. | One model/configuration selected only on train/development data; weights, seed, package versions, code revision, and artifacts frozen; custodian approves the one-shot test opening. |
| **P2.5 — One-shot held-out evaluation** | Open held-out relevance and eligibility labels once; run the frozen analyses and compute registered metrics/intervals/resources. | P2.4 frozen and test access logged. | All registered primary, secondary, family-aware, and sensitivity results, N/A reasons, per-task outputs, bootstrap records, exclusions, and provenance checks are captured. No post-hoc retuning or replacement of tasks/candidates. |
| **P2.6 — Interpretation and release review** | Interpret results and decide whether a public research report is justified. | P2.5 complete; privacy, source, and publication review complete. | Report separates native and oracle-filtered findings, pool coverage and catalogue recall, proposed design and observed results, and limitations; no unsupported generalization or performance claim. |

## Future implementation review (not included in this proposal)

A separate implementation review is required before executable Phase II tooling is used. It should specify and test the benchmark manifest, structural and cross-record validation, annotation lifecycle, candidate-pool replay, native R2/R3 fidelity, H1 bootstrap replay, label custody, reviewer authorization, and public-release claim verification. This proposal does not provide or certify those tools.

The proposed workflow remains subject to human approval and feasibility review. It does not select Option A or B, establish assessor independence or consent, prove source rights or representativeness, authenticate external custody, authorize acquisition, or freeze the protocol.

## Stop conditions

Pause before benchmark acquisition if source terms or access fail review, exact family-group allocation is infeasible, candidate identity/provenance cannot be reconstructed, the final A/B budget is unapproved, or the intended pool cannot be filled under the predeclared rules. Pause before annotation if the calibration gate fails, assessors are not independent, the 25% disagreement pause rule is met, or privacy/consent/custody is unresolved. Pause before model work if Track A/Track B separation, score-only fidelity, common-pool integrity, record validation or split isolation fails. Never replace difficult or unfavorable test records after labels are visible; any protocol change requires a new version and an untouched test partition.
