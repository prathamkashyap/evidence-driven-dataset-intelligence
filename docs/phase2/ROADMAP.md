# Phase II staged roadmap

**Status: proposed sequence.** Each stage is a gate; do not start the next stage until exit evidence is reviewed and recorded.

| Stage | Work | Entry criteria | Exit criteria |
|---|---|---|---|
| **P2.0 — Protocol review and freeze** | Review the task frame, candidate policy, rubric, metric definitions, statistical plan, assessor independence, and resource budget. | This design package is reviewed against the current Phase I code, configuration, and approved paper. | Authors approve one version; schemas validate; task and candidate manifests remain empty until curation; protocol/config/schema hashes are committed before collection. |
| **P2.1 — Task/candidate curation** | Curate 30 novel task briefs; prepare a versioned catalogue snapshot and candidate pools without using labels. | P2.0 frozen; source access and reuse terms reviewed. | All task/pool records are sourced, deduplicated, hashed, split 12/6/12, and frozen; no M8 task or exact M8 candidate snapshot is reused; exclusions and source gaps recorded. |
| **P2.2 — Independent annotation** | Train two independent assessors; annotate every frozen pair blind; adjudicate registered disagreements. | P2.1 frozen; assessors and custodian appointed; consent/privacy and source-display rules approved. | At least two independent first-pass judgments per pair, adjudications preserved, agreement/uncertainty and assessability reported, final test labels sealed. If adjudication exceeds the 25% pause threshold, revise and re-annotate under a new protocol version. |
| **P2.3 — Baseline and pipeline lock** | Implement only the evaluation adapter needed to export comparable frozen-baseline rankings; verify metrics on synthetic unit fixtures that contain no benchmark labels. | P2.2 complete; test labels remain sealed. | Adapter, feature definitions, baseline configs, evaluation code, exclusion rules, hashes, and resource logging are reviewed and frozen. No learned model is tuned on test data. |
| **P2.4 — Train/development model selection** | Fit the single pairwise linear ranker on train labels; choose regularization on development tasks; run registered feature ablation. | P2.3 frozen; train/development labels available. | One model/configuration selected using only train/development data; weights, seed, package versions, code revision, and artifacts frozen; final-test access approved by custodian. |
| **P2.5 — One-shot held-out evaluation** | Open test labels once; run frozen baselines and selected model; compute registered metrics/intervals and resource measurements. | P2.4 frozen and test-label custody logged. | Complete registered results, exclusions, negative/null findings, per-task outputs, bootstrap intervals, resource records, and provenance checks are committed. No post-hoc retuning on the test set. |
| **P2.6 — Interpretation and report** | Interpret results against the Phase I baseline and limitations; decide whether further research is justified. | P2.5 output and audit complete. | Public report distinguishes proposed design, measured result, exploratory analysis, and N/A; no unsupported generalization or performance claim. |

## Stop conditions

Pause before annotation if assessors are not independent of system/query/candidate curation, task/candidate source terms are unclear, candidate identity or provenance cannot be reconstructed, test-set custody is unavailable, or the stated human-hour budget is infeasible. Pause before model work if required labels, schema validation, split isolation, or baseline adapters fail. Do not replace failed datasets/tasks or amend the test set after labels or rankings are visible without a versioned protocol amendment and a fresh untouched test partition.
